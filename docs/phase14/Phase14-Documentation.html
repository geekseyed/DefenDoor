PART 1 — PORTABILITY GUIDE

1. Architecture Overview

Derived flags: IsFullyCapable = IsAdmin && CanReadRegistry && PowerShell && NetExe; HasCriticalDeficiencies = !CanReadRegistry || !PowerShell.

2.2 VM detection

DetectIsVirtualMachine() inspects:

  1. BIOS — HKLM\HARDWARE\DESCRIPTION\System\BIOS values SystemManufacturer, SystemProductName, BIOSVersion against indicators: VMware, VirtualBox, Hyper-V, QEMU, KVM, Xen, Parallels, Virtual Machine, VM.
  2. Disk — HKLM\SYSTEM\CurrentControlSet\Services\Disk\Enum for values containing Virtual, VMware, or QEMU.

2.3 Performance tier rules

ConditionTier
ProcessorCount < 2 OR IsVirtualMachineSlow
ProcessorCount < 4 OR TotalMemoryMB < 4096Medium
OtherwiseFast

2.4 Caching

  • Result stored in _cachedProfile under a private lock.
  • DetectEnvironmentAsync() returns cached profile on subsequent calls.
  • Quick methods fall back to lightweight checks when cache is empty.

2.5 Warnings collected

Sources: CachedProcessRunner.cs, ProcessRunner.cs.

4.2 TTL / failed results / thread-safety

  • TTL from ScannerConfiguration.CacheMaxAgeMinutes (default 30).
  • Failed results (ExitCode != 0) are never cached.
  • Storage: ConcurrentDictionary; stats via Interlocked.
  • Invalidate(pattern) removes keys starting with pattern; InvalidateAll() clears all.

4.3 Current consumers

PasswordLengthCheck and UserRightsCheck still use private Process.Start helpers and do not consume the cache layer on this branch.

6. Running on a New Machine

  1. Install .NET 8 (Windows x64).
  2. Deploy binaries or dotnet build.
  3. Optionally set $env:ASPNETCORE_ENVIRONMENT to Production / Development / AirGapped.
  4. Ensure %LOCALAPPDATA%\DefenDoor\Data is writable.
  5. Run: dotnet run --project ISCM.Web.
  6. Confirm startup shows Catalog Integrity Validation: PASSED.
  7. Execute Full scan; verify findings count vs registered checks.

PART 2 — DEPLOYMENT CHECKLIST

1. Pre-deployment requirements

RequirementDetail
Runtime.NET 8 (Windows)
OSWindows 10/11 or Server 2019+
Storage%LOCALAPPDATA%\DefenDoor\Data writable
AdminNot required for scan-only; required for remediation
ToolsPrefer powershell, net, secedit, auditpol for full coverage

2. Profile selection

ProfileWhen to use
DevelopmentLocal debugging; short timeouts; verbose logging
ProductionNormal production; longer timeouts; quiet logging
AirGappedIsolated networks; sequential; fingerprint off; 24h cache

3. Per-profile checklists

Development

  • ASPNETCORE_ENVIRONMENT=Development
  • Confirm short timeouts acceptable
  • Expect verbose + raw output logs
  • Cache TTL = 5 minutes

Production

  • ASPNETCORE_ENVIRONMENT=Production
  • Confirm storage path
  • Max scan duration 120 min OK
  • Fingerprint + freshness enabled
  • Logging Warning/Error only

AirGapped

  • ASPNETCORE_ENVIRONMENT=AirGapped
  • No external network dependency required for scanning
  • Accept sequential execution
  • Fingerprint validation disabled by design
  • Long timeouts and 24h cache

4. Post-deployment verification

  1. Startup shows Catalog Integrity Validation: PASSED
  2. Run Full scan
  3. Findings count equals registered check count (22 checks registered in Program.cs)
  4. Optional: inspect process cache stats after second scan
  5. Review adaptive profile reasoning for unexpected skips

5. Rollback procedure

  1. Stop process
  2. Redeploy previous known-good binaries
  3. Restore storage path if needed
  4. Restore previous ASPNETCORE_ENVIRONMENT
  5. Start and confirm catalog validation

6. Security notes

  • Admin required only for remediation / registry writes; scan-only can run non-elevated.
  • AirGapped profile does not introduce external network calls for scanning.
  • ProcessRunner uses UseShellExecute=false, CreateNoWindow=true; errors returned in ProcessResult.
